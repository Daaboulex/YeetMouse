* Description
  *YeetMouse* is a kernel module that allows for fast and customizable mouse acceleration.
  I created *YeetMouse* to build upon the great work of /Klaus Zipfel's/ *[[https://github.com/systemofapwne/leetmouse][LeetMouse]]* and add features such as =Jump= (at first it was mostly it, the Jump acceleration mode).
  But it quickly grew into something bigger as I decided to add a GUI to it for better control.

* Installation & Uninstallation

** Preparation
   + Make sure you have the required build tools (=build-essentials= on Debian), =dkms=, and the =linux-headers= for your currently installed kernel.
   + The GUI also requires OpenGL and GLFW development files to build.
   + The installation script should be run as a *regular user* and will use =sudo= internally when needed.

*** Installation
   The easiest way to install YeetMouse is to use the provided =./install.sh= script:
   #+begin_src sh
   git clone https://github.com/AndyFilter/YeetMouse.git
   cd YeetMouse
   ./install.sh
   #+end_src

   The installer always installs the driver, =yeetmousectl=, config file, profile directory =/etc/yeetmouse=, service, and uninstaller.
   The GUI is built and installed *optionally*, if its dependencies are present.

   If your user is added to the =yeetmouse= group during installation (should be by default), you must start a new login session before the GUI can access the driver.
   Logging out and back in is usually enough; on some systems a reboot may be required.

** GUI dependencies
   The GUI requires:
   + OpenGL
   + GLFW3 development files
   + =pkg-config=

   If these are missing, the main installation still succeeds, but the GUI is skipped.
   Once the dependencies are installed, you can install the GUI separately with:
   #+begin_src sh
   sudo make install_gui
   #+end_src

** Configuration model
   YeetMouse keeps its settings in plain files:
   + =/etc/yeetmouse/default.conf=, the default config, used by every mouse that =devices.conf= does not list; =/etc/yeetmouse.conf= is a link to it for tools that read the old path,
   + =/etc/yeetmouse/profiles/<name>.conf=, named profiles, each a curve in the same format,
   + =/etc/yeetmouse/devices.conf=, one line per mouse naming its profile, DPI pre-scale and timing.

   Runtime configuration is handled by =yeetmousectl=:
   #+begin_src sh
   yeetmousectl apply /etc/yeetmouse/default.conf
   yeetmousectl load
   yeetmousectl status
   yeetmousectl dump
   yeetmousectl save my-config.conf
   #+end_src

   On systemd-based systems, a udev rule gives =/dev/yeetmouse= to the =yeetmouse= group and starts =yeetmouse.service= whenever the driver loads, at boot or by hand. The service runs =yeetmousectl setup=, which moves an older =/etc/yeetmouse.conf= into =/etc/yeetmouse/default.conf= and links it, records touchpad resolutions, and runs =yeetmousectl load=. Unloading the module stops the service, so the next load applies everything again.

** Uninstallation
   If YeetMouse was installed system-wide, use:
   #+begin_src sh
   sudo yeetmouse-uninstall
   #+end_src

   The repository =./uninstall.sh= script will prefer the installed uninstaller if it exists, and otherwise fall back to the repository copy.


** Running the GUI
*** Permissions
   The GUI is intended to run *without sudo*.
   Access to the driver parameters is granted through the =yeetmouse= group.

   After installation, your user may be added to that group automatically. This change applies only to *new login sessions*.
   If the GUI cannot access the driver right after installation:
   + log out and log back in,
   + or reboot if your desktop session does not fully refresh group membership.

*** Prerequisites
   The GUI requires:
   + OpenGL
   + GLFW3 development files

   Exact package names depend on the distribution. On Debian/Ubuntu systems, this usually means packages such as:
   #+begin_src sh
   sudo apt install libglfw3 libglfw3-dev
   #+end_src

*** Building
   To build only the GUI:
   #+begin_src sh
   cd gui/
   make
   #+end_src

*** Starting
   After installation, simply run:
   #+begin_src sh
   yeetmouse
   #+end_src

   The GUI should not need =sudo=, provided your user session already has the =yeetmouse= group.

*** Profiles and devices
   + The picker at the top of the parameters panel chooses what the editor changes: the default config or a named profile, each labelled with the connected mice it drives, as the driver reports them. The GUI opens on the profile those mice share.
   + Under each curve type in the mode column sit the saved profiles that use it; clicking one opens it. Clicking the curve type shows that curve with its defaults, or what was changed this session, keeping the sensitivity.
   + =Apply= uses the edited settings now and leaves the file alone. =Save= writes the file, then applies it. =Reset= puts the saved file back, on screen and in the driver. =Defaults= sets the current curve to its defaults. The line under the picker says =Edited=, =Applied, not saved= or =Saved=, read back from the driver, and switching away from unsaved changes asks first.
   + =Save as new profile=, =Delete profile= and =Copy into default= sit below the picker. A running game's profile shows as =Game running: <profile>=.
   + The =Devices= menu lists each mouse the driver handles, with the line the driver resolved for it. Pick =Default= or the receiver's line, a profile or =Disabled=, give a mouse paired through a receiver its own line, or set a line's DPI (=DPI...=, or =DPI and timing...= with Raw Accel features on). Mice in =devices.conf= that are not connected appear under =Not connected=, where =Forget= removes their line. Touchpads are listed too, as described under Touchpads below.
   + =File=, =Import= loads a YeetMouse config (or an old config.h) or one Raw Accel profile into the editor, or adds every profile and mouse of a Raw Accel settings.json. =File=, =Export= saves the editor's settings as a YeetMouse config, as config.h for older YeetMouse that builds settings into the driver, or as a Raw Accel profile, or saves the default, every profile and every mouse as one Raw Accel settings.json.
   + =Edit= copies the editor's settings as YeetMouse config text and pastes such text back into the editor.
   + =View=, =Raw Accel features= shows the settings YeetMouse adds for Raw Accel: timing, truncate carry, clock on any report, exact math, lp norm, domain and range weights, smoothing, axis snap, speed cap, directional ratios, a separate vertical curve, Classic's input offset, the Sens Cap of Classic and Power, and tables of velocities. Off hides all of them, including the timing in =Devices=, =DPI...=; settings a curve already uses keep working in the driver.
   + The chart's right-click menu has ImPlot's =Auto-Fit= per axis, which follows the curves and ignores the mouse speed dots; double-clicking the chart fits it once.

   #+begin_src sh
   sudo pacman -R yeetmouse yeetmouse-driver-dkms yeetmouse-tools yeetmouse-gui
   #+end_src

** Other distros
   Other distributions' package-managers are not yet fully supported, so manual installation may be required.

*** Installation
   The easiest method is:
   #+begin_src sh
   ./install.sh
   #+end_src

   This installs:
   + the DKMS source tree,
   + the kernel module through DKMS,
   + =yeetmousectl=,
   + the default config in =/usr/share/yeetmouse/default.conf=, copied to =/etc/yeetmouse/default.conf= when that file is missing,
   + the profile directories =/etc/yeetmouse= and =/etc/yeetmouse/profiles=, writable by the =yeetmouse= group,
   + the systemd service (if systemd is present),
   + and the GUI files if built/installed through the project Makefile.

   If systemd is not present, run these after the module loads, from your init system:
   #+begin_src sh
   chgrp yeetmouse /sys/module/yeetmouse/parameters/* /dev/yeetmouse
   /usr/bin/yeetmousectl setup /etc --seed /usr/share/yeetmouse
   /usr/bin/yeetmousectl load
   #+end_src

   *Uninstallation*
   Use the installed uninstaller:
   #+begin_src sh
   sudo yeetmouse-uninstall
   #+end_src

   The uninstaller disables the service, removes installed files, removes the DKMS module, and asks whether to remove =/etc/yeetmouse=, with the default config, profiles and =devices.conf=, and the =/etc/yeetmouse.conf= link. =--keep-config= or =--purge-config= answers that question in advance.

* Manual compile & insmod
   If you want to compile this module only for testing purposes or development, you do not need to install the whole package to your system.

   Compile the module, remove previously loaded modules and insert it:
   #+begin_src sh
   make clean && make
   sudo rmmod yeetmouse
   sudo insmod ./driver/yeetmouse.ko
   #+end_src

* Command line usage
** Applying a config
   Apply a config file to the running driver as its default:
   #+begin_src sh
   yeetmousectl apply /etc/yeetmouse/default.conf
   #+end_src

** Dumping current runtime values
   Print the driver parameters; it fails when the driver refused them, because they are then not what is live:
   #+begin_src sh
   yeetmousectl dump
   #+end_src

** Saving current runtime values
   Save the currently active settings to a file:
   #+begin_src sh
   yeetmousectl save my-config.conf
   #+end_src

** Profiles
   A profile is a curve saved as =/etc/yeetmouse/profiles/<name>.conf=, in the format of the default config but without =preScale=, =minTime=, =maxTime= and =fixedTime=, which belong to a mouse's line in =devices.conf=.
   A name uses letters, digits, =.=, =_= or =-=, starts with a letter or digit, has at most 31 characters and is not =disabled=.
   #+begin_src sh
   yeetmousectl profile list
   yeetmousectl profile save power my-config.conf
   yeetmousectl profile remove power
   #+end_src

   =profile list= prints each profile with the devices that use it.
   =profile save= stores the curve of a config file, leaving out its DPI and timing, and loads it into the driver.
   =profile remove= is refused while a device line or a running game uses the profile.

** Devices
   =/etc/yeetmouse/devices.conf= holds one line per mouse, named by its vendor and product id.
   The driver looks each mouse up by that id, so a listed mouse gets its line as soon as it connects, with no udev rule and no daemon.
   Unlisted mice use the default config, =/etc/yeetmouse/default.conf=.
   #+begin_example
   046d:c539 power preScale=1 minTime=0 maxTime=100 fixedTime=0
   #+end_example

   =preScale= is the mouse's DPI pre-scale (1000 / DPI matches Raw Accel's DPI setting), and =minTime=, =maxTime= and =fixedTime= set its packet timing.
   A line =<vendor:product> disabled= passes that mouse's movement through unchanged.

   =yeetmousectl= writes these lines and loads them into the driver:
   #+begin_src sh
   yeetmousectl device list
   yeetmousectl device set 046d:c539 power
   yeetmousectl device set 046d:c539 power preScale=1.25
   yeetmousectl device set 046d:c539 disabled
   yeetmousectl device remove 046d:c539
   #+end_src

   =device list= shows each connected mouse with its profile, or =default=, and the listed mice that are not connected.
   A new line takes its DPI and timing from the default config, and =key=value= arguments override them.
   =device remove= returns the mouse to the default config.

** Loading and checking
   #+begin_src sh
   yeetmousectl load
   yeetmousectl check
   #+end_src

   =load= applies the default config, then loads every profile and =devices.conf= into the driver, as the service does. Every step runs even when one fails, and the command exits 1 naming each failure; with a driver older than the tools it changes nothing and says to reboot. A malformed or invalid line, or one whose profile did not load, is left out and named, and the other lines still load.
   =check= validates the default config, the profiles and =devices.conf= with the driver's own checks, without touching the driver, and lists every problem.
   =yeetmousectl check <dir>= checks =<dir>/yeetmouse/= instead.

** Checking what the driver holds
   #+begin_src sh
   yeetmousectl status
   #+end_src

   =status= reads the driver's own state from =/dev/yeetmouse= and says whether the default config, each profile and each =devices.conf= line in the driver match their files, whether the driver refused the last default and why, which game holds a profile, and which curve each connected mouse uses, through its receiver's line when it has none of its own. It exits 1 when anything differs.
   =cat /dev/yeetmouse= prints the same state as the driver writes it.

** Running a game on its own profile
   #+begin_src sh
   yeetmousectl run power -- %command%
   #+end_src

   Put this in a game's launch options, where Steam's =%command%= stands for the game.
   While the game runs, every mouse that is not disabled, including one plugged in mid-game, uses the profile's curve with its usual DPI and timing.
   =yeetmousectl= holds =/dev/yeetmouse= open and the driver drops the game's profile when that handle closes, so the saved curves return when the game exits or the wrapper is killed.
   With two games running, the newer one wins until it exits.
   If the profile is missing or broken, the game still starts on the saved curve and =notify-send= shows why.

** Importing and exporting Raw Accel settings
   =yeetmousectl= reads and writes Raw Accel 1.7 =settings.json= files.
   A conversion is exact or refused. A setting YeetMouse cannot reproduce stops it with a message that names the setting, and files older than Raw Accel 1.7 are refused.
   #+begin_src sh
   yeetmousectl import-rawaccel settings.json > my-config.conf
   yeetmousectl import-rawaccel settings.json --merge
   yeetmousectl import-rawaccel settings.json --into ./converted
   yeetmousectl export-rawaccel > settings.json
   yeetmousectl export-rawaccel my-config.conf > settings.json
   yeetmousectl export-rawaccel --from /etc > settings.json
   #+end_src

   + =import-rawaccel <file>= prints Raw Accel's first profile, with its default device settings, as a YeetMouse config. A device id from the file as a second argument prints that device's profile and settings instead.
   + =--merge= adds every Raw Accel profile to =/etc/yeetmouse/profiles= and every device to =devices.conf=, then loads them. It refuses a profile name or a device that already exists and leaves the default config unchanged.
   + =--into <dir>= writes =<dir>/yeetmouse/default.conf=, =<dir>/yeetmouse/profiles/= and =<dir>/yeetmouse/devices.conf=, and refuses if any of those files exists already.
   + =export-rawaccel= converts the live driver settings, or the config file given, to one Raw Accel profile. =--from <dir>= exports =<dir>/yeetmouse/default.conf=, every profile and =devices.conf=. A device line keeps the Windows id it was imported with as =windowsId==, and a line without one is left out and named on stderr.
   + An export needs Raw Accel's timing, which is =truncateCarry=1=, =clockOnAnyReport=1= and a =minTime= above 0. The GUI's Raw Accel section sets them.

** Touchpads
   Touchpads are listed with the mice, but the driver does not curve them, because libinput in the compositor turns finger positions into motion.
   YeetMouse can hand a profile's curve to KWin as a libinput custom acceleration curve once KWin takes one (KWin merge request 6937). Until then the GUI's touchpad entry says KWin cannot take touchpad curves yet, and =yeetmousectl touchpad= is refused. Once it can, the GUI's touchpad entry lists a curve per profile, and =KWin adaptive= or =KWin flat= (=yeetmousectl touchpad <vendor:product> --kwin-adaptive= or =--kwin-flat=) hands the touchpad back to KWin's own acceleration.
   #+begin_src sh
   yeetmousectl touchpads
   yeetmousectl touchpads --record
   yeetmousectl touchpad <vendor:product> power
   #+end_src

   =touchpads= lists the connected touchpads with their resolution.
   =--record= stores each touchpad's resolution in =/run/yeetmouse/touchpads=. It needs root, and the service runs it.
   =touchpad= samples a profile into KWin's curve for that touchpad. A profile that needs more than a single speed curve, such as one with smoothing, rotation, angle snapping or a separate vertical curve, is refused.

* FAQ
** How to set custom parameter value?
- Ctrl + Left Click on the parameter box to start inputting the values manually.

** How are settings preserved between reboots?
- Settings are stored in =/etc/yeetmouse/default.conf=, with named profiles in =/etc/yeetmouse/profiles= and per-mouse lines in =/etc/yeetmouse/devices.conf=.
- To apply them immediately:
  #+begin_src sh
  yeetmousectl apply /etc/yeetmouse/default.conf
  yeetmousectl load
  #+end_src
- On systemd systems, =yeetmouse.service= does both whenever the driver loads.
- To export the currently active settings:
  #+begin_src sh
  yeetmousectl save my-config.conf
  #+end_src

** Why does the GUI say it cannot read /dev/yeetmouse?
- Your user was likely added to the =yeetmouse= group during installation.
- Group changes usually apply only to a new login session.
- Log out and log back in, or reboot if necessary.

** Mouse feels off (too fast / slow)
- On some distros (for example Ubuntu 20.04) the system adds an additional sensitivity on top of the driver.
  To combat this, configure the desktop sensitivity appropriately.
  For Ubuntu 20.04 users, one useful value is:
  #+begin_src sh
  gsettings set org.gnome.desktop.peripherals.mouse speed -0.666
  #+end_src

** How do I convert my RawAccel settings?
- Run =yeetmousectl import-rawaccel settings.json= on a Raw Accel 1.7 file. It converts exactly, or refuses and names the setting it cannot reproduce. See Importing and exporting Raw Accel settings above.
- In the GUI, =File=, =Import=, =Raw Accel profile= loads one profile into the editor, and =Raw Accel profiles and mice= adds all of them to =/etc/yeetmouse=.
- Files from Raw Accel versions before 1.7 are refused.
- YeetMouse's own /Motivity/ mode has no Raw Accel equivalent, so a curve that uses it cannot be exported.

** How to apply LUT curves as velocity (and use the EPP (Windows default acceleration) curve)?
- Turn on =View=, =Raw Accel features=, then tick =Values are velocities= in the LUT or custom curve mode, or set =lutVelocity=1= in the config. Each y value is then an output speed, divided by the input speed, as Raw Accel does for a lookup table with =Gain / Velocity= on.
- For the EPP (Enhance Pointer Precision) curve specifically, use the config from this comment: https://github.com/AndyFilter/YeetMouse/issues/67#issuecomment-3620653542.
